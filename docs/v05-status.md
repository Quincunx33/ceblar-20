# ceblar-20 v0.5 status

## Implemented

The v0.5 branch now has an IRQ0-driven, frame-aware round-robin path. Two kernel workers are created before the embedded init process, sleep in 500 ms intervals, and are alternated by PIT timer interrupts. Exited workers are removed from the ready path, while the original ring-3 init remains schedulable. The v0.4 `user: hello` smoke test continues to run in the same boot.

The storage layer includes a bounded ATA primary-master PIO driver with IDENTIFY probing, timeout checks, 28-bit LBA sector reads and writes, a raw `hda` VFS descriptor at fd 3, and length-safe console writes. FAT32 mounting parses a boot sector or MBR FAT32 partition, validates BPB geometry, follows FAT cluster chains, performs root-directory 8.3 lookup, reads file contents across sector and cluster boundaries, and exposes root enumeration. The filesystem layer is read-only; raw ATA writes remain available through fd 3.

Syscall hardening now walks every page in the current address space for user buffers, checks write permissions for output buffers, validates bounded user strings, and maps `SYS_MMAP` into the current process address space. `SYS_EXEC` loads a bounded file image through VFS, validates it with the ELF32 loader in a new address space, maps a fresh user stack, and only then replaces the current process image. `SYS_WAIT` records a wait target and status pointer, blocks through the interrupt-frame scheduler path, and is woken by a matching child exit. The diagnostic shell now initializes its line length and supports `ps` and `exec <path>`.

## Verification evidence

The clean ISO build completed with the repository’s strict freestanding flags. A no-disk QEMU run produced:

```text
ata: primary master absent
scheduler: workers queued for preemption test
userspace: launching ring3 init
worker pid=1 tick=10
worker pid=2 tick=20
user: hello
worker pid=1 tick=520
worker pid=2 tick=530
worker: sleep cycle complete
worker: sleep cycle complete
```

A QEMU run with `build/test-fat32.img` attached as the IDE disk produced:

```text
ata: primary master ready, LBA28 PIO
fat32: mounted, root cluster ready
fat32: HELLO.TXT read ok
vfs: fd3=hda raw device
user: hello
```

The fixture is generated by `tools/make_test_disk.sh`, which creates a 64 MiB FAT32 image and installs `HELLO.TXT` without committing the generated image.

```sh
  -display none -serial stdio -monitor none -no-reboot
```

## Boundaries

The QEMU evidence directly validates ATA identify, FAT32 mount, a real FAT32 file read, IRQ0 worker alternation, and the preserved embedded ring-3 syscall. Disk-backed `SYS_EXEC` and blocking `SYS_WAIT` are implemented and compile-validated, but they do not yet have a dedicated user-image integration fixture in the boot test. Fork remains eager-copy, mmap is a single-page primitive, descriptor inheritance and complete zombie resource reclamation remain v0.6 hardening work, and the legacy cooperative `context_switch.S` path is not used by frame-aware IRQ0 preemption.
